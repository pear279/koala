## 一、当前状态

### 1.1 项目定位

情绪记录与植物养成结合的 AI 陪伴应用。用户与 AI 对话记录心情，情绪转化为「种子」，在个人森林中培育成植物。

**当前阶段：前端原型，无后端。** 界面可交互浏览，数据来自本地演示数据。

### 1.2 技术栈

| 用途 | 选择 | 说明 |
| --- | --- | --- |
| 构建 | Vite 6 | 产物为纯静态文件 |
| 框架 | Vue 3（SFC + Composition API） | 组件化消除页面间重复 |
| 路由 | vue-router 4（hash 模式） | 静态托管无需服务端重写规则 |
| 样式 | 原生 CSS + CSS 变量 | 无预处理器、无 UI 框架 |

运行依赖仅 `vue` 与 `vue-router` 两项。构建产物 gzip 后约 44KB。

### 1.3 页面完成度

6 个页面已全部脱离设计稿截图，均为真实 DOM 结构：

| 路由 | 页面 | 状态 |
| --- | --- | --- |
| `/` | 首页（幸运花语 + AI 性格） | 已组件化 |
| `/forest` | 我的森林（植物图鉴 + 培育进度） | 已数据驱动 |
| `/story` | 故事库（心情日历 + 社区入口） | 已还原，日历跟随系统时间 |
| `/seed` | 我的种子（记录列表 + 入口卡 + 模式卡） | 已还原 |
| `/message` | 消息（分组列表） | 已还原 |
| `/my` | 我的（个人资料） | 已还原，适配已重构 |

### 1.4 代码结构

```

├── router/index.js          # 6 条路由 + 兜底重定向
├── config/navigation.js     # 导航单一数据源

│   ├── ResourceBar.vue      # 养成资源进度条
│   ├── ChatPanel.vue        # 右侧对话面板（可交互）
│   ├── MoodCalendar.vue     # 心情日历

└── pages/                   # 6 个页面
```

### 1.5 适配现状

桌面优先。三栏宽度使用 `clamp()` 随视口平滑缩放，无断点跳变：

| 变量 | 取值 |
| --- | --- |
| `--sidebar-width` | `clamp(148px, 13vw, 200px)` |
| `--chat-panel-width` | `clamp(280px, 22vw, 380px)` |
| `--content-gutter` | `clamp(20px, 3vw, 64px)` |
| `--layout-min-width` | `900px` |

「我的」页为全宽布局（无两侧栏），卡片限宽 1180px 居中，内部使用容器查询（`container-type: inline-size` + `cqi`）随卡片宽度缩放。

**900px 以下会出现横向滚动，移动端未适配。**

## 二、已识别的技术债

按影响面排序。

### T1. 无状态管理层（阻塞性）

**现状**：所有状态都是组件内 `ref`。

- `ChatPanel` 发送的消息切页即丢
- `MyPage` 编辑的表单不持久
- 资源值（阳光/水/肥料）在 `ResourceBar` 与 `GrowthProgress` 各读一次 mock，互不同步

**影响**：这是所有交互功能落地的前提。「领资源 → 资源值变化 → 培育进度推进」这条产品主循环目前无法实现。

### T2. `mock.js` 职责过载

**现状**：单文件约 290 行，混合 12 个不同领域的导出（用户、资源、对话、植物、日历、社区、消息、培育、种子）。

**影响**：任何领域改动都要动同一文件，冲突面大；也让「哪些数据将来由接口提供」这件事无法从文件结构上体现。

### T3. 交互多为空壳

无行为的按钮清单：

| 页面 | 按钮 |
| --- | --- |
| `/forest` | 晒太阳、浇水、施肥、做任务领资源 |
| `/seed` | 种子宝箱、添加祈福、合种模式、赠送模式 |
| `/my` | 升级VIP、点击签到、邀请好友、设置 |
| `ChatPanel` | 转化成种子、聊天记录、全屏、关闭 |

**影响**：原型可看不可用，无法进行有效的可用性验证。

### T4. 无测试、无 lint

**现状**：`package.json` 仅有 `dev` / `build` / `preview` 三个脚本。

**风险点**：以下纯函数边界条件密集，目前无任何回归保护。

- `MoodCalendar` 的 `weeks` 计算（跨月、跨年、闰年、周首日）
- `formatRelativeTime`（自然日边界、未来时间、非法输入）
- `createCalendarRecords`（月份解析、补位周范围）

### T5. 移动端完全未适配

`--layout-min-width: 900px`，低于此宽度横向滚动。三栏布局在移动端不可用。

### T6. 图片资源未优化

`public/images` 共 34 张 PNG，其中 9 张超过 100KB：

| 文件 | 大小 |
| --- | --- |
| `story/community-2.png` | 264 KB |
| `story/seed1.png` | 345 KB |
| `story/seed2.png` | 245 KB |
| `plant/growth-progress-0.png` | 218 KB |
| `plant/9.png` | 169 KB |
| `seed/treasure-chest.png` | 162 KB |
| `seed/blessing.png` | 153 KB |
| `story/1-3.png` | 128 KB |
| `enfp.png` / `entp.png` | 各约 105 KB |

其中 `community-1/2.png`、`seed1/2.png`、`growth-progress-0.png` 已仅作设计稿对照用途，不参与页面渲染，但仍在仓库与构建产物中。

### T7. `archive/` 目录已无引用

- `archive/prototype-html/`：Figma 还原稿，13 个文件
- `archive/frontend-demo-1/`：早期交互草稿，26 个文件（含 8 个 0 字节占位 PNG）

已完成还原工作，这些文件不再被任何代码引用。

### T8. 文档与代码脱节

`README.md` 中「页面与完成度」「适配范围」「后续计划」三节内容均已过期，仍描述「3 个页面仍为截图」「1600px/1200px 两级断点」等已不存在的状态。

## 三、优化规划

### 阶段一：打通数据链路（阻塞项，建议优先）

> 目标：让状态可共享、可持久，为所有交互功能铺路。

#### 1.1 引入 Pinia

按领域建 store：

| Store | 职责 |
| --- | --- |
| `useUserStore` | 用户资料、邮箱绑定、登录态 |
| `useResourceStore` | 阳光/水/肥料数值、领取冷却 |
| `usePlantStore` | 当前培育植物、成长阶段、图鉴解锁 |
| `useChatStore` | 对话记录、草稿、情绪标签 |

**要点**：资源值必须单一来源，`ResourceBar` 与 `GrowthProgress` 都从 store 读，消除当前的双份 mock 读取。

#### 1.2 抽 `api/` 层

```
src/api/
├── client.js       # 统一请求封装：超时、错误规范化、鉴权头
├── user.js
├── resource.js
├── plant.js
├── calendar.js
└── message.js
```

先返回 mock 数据（可加人为延迟以暴露 loading 态问题），组件只依赖接口签名。后端接入时仅改 `api/` 内部实现。

#### 1.3 拆分 `mock.js`

按领域拆入 `src/mocks/`，与 `api/` 模块一一对应。拆分后 `data/mock.js` 移除。

**产出**：状态可跨页共享；接口契约明确；单个领域改动不影响其他文件。

---

### 阶段二：质量保障

> 目标：让重构有回归保护。

#### 2.1 工程化配置

| 工具 | 用途 |
| --- | --- |
| ESLint + `eslint-plugin-vue` | 代码规范 |
| Prettier | 格式统一 |
| Stylelint | CSS 规范，重点校验「不得使用颜色/间距字面量」 |
| Vitest | 单元测试 |

新增 npm 脚本：`lint`、`lint:fix`、`format`、`test`、`test:coverage`。

#### 2.2 优先补测的纯函数

按风险排序：

1. `MoodCalendar` 的 `weeks` —— 用例：闰年 2 月、1 月/12 月跨年、当月 1 日恰为周日、6 周月份
2. `formatRelativeTime` —— 用例：59 秒、61 秒、23:59 与次日 00:01、未来时间、`NaN`、`null`
3. `createCalendarRecords` —— 用例：非法月份、跨年补位、返回值确定性（同参数两次调用结果一致）

#### 2.3 CI 检查

`lint` + `test` + `build` 三步，PR 必须通过。

**产出**：日期计算类逻辑有回归保护；样式规范由工具强制而非靠人工评审。

### 阶段三：核心交互闭环

> 目标：让原型真正可用，可进行可用性验证。

#### 3.1 主循环：养护 → 资源 → 成长

```
点击「晒太阳」
  → 校验今日是否已领取
  → 资源值增加（写入 store）
  → 培育进度按规则推进
  → 达阈值时成长阶段跃迁
  → 图鉴解锁新植物
```

需先明确的规则（**待产品确认**）：

- 每种资源的每日领取上限与冷却时间
- 资源量与进度百分比的换算关系
- 成长阶段的阈值划分（当前 mock 为「幼苗阶段 / 25%」）
- 阶段跃迁与图鉴解锁的对应关系

#### 3.2 对话 → 种子

`ChatPanel` 的「转化成种子」应产出一颗种子并进入 `/seed` 页记录列表，形成两页之间的数据联动。

#### 3.3 其余按钮

签到、邀请好友、合种、赠送等。建议先做「签到」——链路最短，可验证 store 与持久化是否可靠。

**产出**：产品主循环可完整走通。

## 四、安全基线

以下条目在接入真实后端与 AI 服务前必须保持。

### 4.1 已落实

| 条目 | 现状 |
| --- | --- |
| 消息渲染禁用 `v-html` | `ChatPanel` 全部使用文本插值 `{{ }}`，注释已声明约束 |
| 密钥不进仓库 | `.gitignore` 已排除 `.env*`（保留 `.env.example`） |
| 无第三方 CDN | 依赖仅 `vue`、`vue-router`，均为本地依赖 |
| 记录数据读取 | `MoodCalendar` 使用 `hasOwnProperty` 校验，避免原型链键污染 |

### 4.2 后端接入时必须落实

| 风险 | 要求 |
| --- | --- |
| **AI 输出为不可信输入** | AI 回复渲染同样禁止 `v-html`。若将来需要富文本，必须走白名单净化（如 DOMPurify），不得直接注入 |
| **越权访问** | 用户资料、邮箱绑定、种子/植物数据的所有接口，服务端必须校验鉴权与资源归属。前端的 `disabled` 属性仅是 UI 提示，不构成任何保护 |
| **密钥泄露** | AI 服务凭证必须放服务端，通过后端代理调用。前端不得持有任何密钥 |
| **XSS** | 用户昵称、情绪标签、记录正文等所有用户可控字段，渲染时一律走文本插值 |
| **SSRF** | 若将来支持「引用外部链接」类功能，需明确是否允许访问内网。默认拒绝内网地址段 |
| **反序列化** | 若引入本地缓存（localStorage 等），读取时必须校验结构，不得直接信任并展开 |
| **依赖供应链** | 新增依赖前评估必要性；定期跑 `npm audit` |

## 六、遗留待确认事项

以下内容在还原过程中无法从设计稿确定，需产品或设计确认。

### 6.1 设计稿识别不清的文案

来源：`public/images/plant/growth-progress-0.png`，原图仅 937×270，小字放大后仍不可辨。

| 位置 | 当前取值 | 说明 |
| --- | --- | --- |
| 浇水资源名 | `缓水` | 疑为「浇水」或「清水」 |
| 三项资源量 | 阳光 120 / 210 / 肥料 300 | 数字需核对 |
| 记录内容日期后缀 | `（最近一次记录）` | 括号内文字不可辨 |
| 记录正文 | 约 240 字占位文案 | 按语感补全，建议直接替换 |

### 6.2 交互语义待定

| 项 | 问题 |
| --- | --- |
| 「明日可领资源」按钮 | 当前实现为 `disabled`。截图中两按钮同为白底，无法判断是否为禁用态 |
| `/story` 共鸣社区入口 | 当前无目标路由，渲染为 `div` 而非链接。需确认目标页面 |
| 日历补位日期的记录 | 截图中非本月日期（如 4/28-4/30）也显示记录条带，当前保留此行为 |

### 6.3 素材待补

| 项 | 现状 | 建议 |
| --- | --- | --- |
| `/seed` 合种/赠送图标 | 手绘内联 SVG，形态接近但非像素级一致 | 从设计稿导出 SVG 替换 |
| `/seed` 模式卡渐变底色 | 用 `--color-primary-dark → --color-primary` 近似 | 提供精确色值 |
| `/seed` 入口卡插画 | 从 `seed1.png` 裁切，含设计稿自带标题胶囊（已用 CSS 白胶囊覆盖并渲染真实文本） | 提供不含标题的干净插画 |

### 6.4 设计稿自身的问题

`community-1.png` 将 2025-05-01 画在**周三**，实际该日为**周四**。当前实现以真实历法为准，因此日期排布与该截图会错开一格。
